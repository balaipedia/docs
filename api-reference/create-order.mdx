---
title: "Create order"
description: "Create an order and send the invitation."
api: "POST https://orders.balaipedia.com/v1/orders"
---

Headers: `Authorization: Bearer YOUR_KEY` and `Content-Type: application/json` (required), and `Idempotency-Key` (optional, recommended).

<Note>
  The `Idempotency-Key` header is optional, but we strongly recommend sending it on every `POST /orders` so the same order is never created twice. When a request times out or the connection drops you cannot know whether the order was created. Repeat the request with the same key and the same email: you get the same order back (header `Idempotent-Replayed: true`) and are never charged twice. Keys are remembered for 24 hours. Reusing a key with a different email returns `422 idempotency_conflict`.
</Note>

<Warning>
  Without the header the request still works and the duplicate-email check (`409 duplicate_order`) still applies, but we cannot recognise a retry as the same request. In particular, retrying a timed-out request that has `allow_duplicate: true` and no key can create and charge a second order.
</Warning>

## Headers

<ParamField header="Idempotency-Key" type="string">
  Optional, recommended. 8-64 characters (letters, digits, `_ . : -`), for example a UUID. Prevents the same order from being created twice when you retry. Store it with your order so a retry reuses it.
</ParamField>

## Body

<ParamField body="email" type="string" required>
  Buyer's email. One address per order.
</ParamField>

<ParamField body="name" type="string">
  Optional. Used in the greeting (max 60 chars).
</ParamField>

<ParamField body="lang" type="string" default="en">
  `"en"` | `"id"`. Language of the email sent to the buyer: English or Indonesian. Default `"en"`. Any other value is rejected with `400`. This is independent of your account currency.
</ParamField>

<ParamField body="reference" type="string">
  Your own order reference (max 64). Returned in responses and webhooks; searchable via the list endpoint.
</ParamField>

<ParamField body="allow_duplicate" type="boolean">
  `true` or `false` only. By default an email that received an invitation in the last 30 days is refused with `409`. Set true to send again (charged). Re-sending is only allowed when the earlier invitation was one of your own orders; otherwise it is still refused with `409`.
</ParamField>

## Response

Returns the [order object](/api-reference/get-order#the-order-object) with status `201 Created`, plus `balance`: your balance after the charge.

## Rejected by validation, `422` (nothing charged)

```json
{"error":{"code":"email_rejected","message":"The email address was rejected by validation. No credit was charged.","reason":"mailbox_full","note":"The recipient's mailbox is full. Ask them to free up space, then retry after 3 hours.","request_id":"req_..."}}
```

`reason` is a stable code you can branch on; `note` is a short human-readable explanation you can log or show.

| reason | Meaning |
|--------|---------|
| `invalid_format` | Not a valid email format. |
| `typo_domain` | Likely typo in the domain; `suggestion` may contain the corrected address. |
| `domain_no_mail` | Domain does not exist or does not accept email. |
| `mailbox_not_found` | The mailbox does not exist. |
| `mailbox_full` | The recipient's inbox is full. Not a permanent block: ask the recipient to free up space and retry the same order after 3 hours. |
| `disposable_email` | Temporary / disposable email service. |
| `address_undeliverable` | This address previously failed or is on our block list. |
| `high_risk` | Flagged as risky (spam trap, abuse, do-not-mail). |
| `invalid_email` | Other validation failure. |

## Other failure responses

Every failure uses the same body, `{"error":{"code","message","request_id"}}`. Branch on `code`, not on `message`. A failed request never creates an order. Credit is charged only on `201`.

| HTTP | code | Example body | What to do |
| --- | --- | --- | --- |
| 400 | `invalid_request` | `{"error":{"code":"invalid_request","message":"Only one email address per order.","request_id":"req_..."}}` | One email per request: no bulk, no list, and no comma-, semicolon- or space-separated addresses. Other messages: `"email" is required.`, `"email" must be a string.`, `"lang" must be "id" or "en".`, `"allow_duplicate" must be a boolean.`, `Request body must be a JSON object.`, `Idempotency-Key must be 8-64 chars (letters, digits, _ . : -).` Fix the request, do not retry unchanged. |
| 400 | `invalid_json` | `{"error":{"code":"invalid_json","message":"Request body must be valid JSON.","request_id":"req_..."}}` | Send valid JSON with `Content-Type: application/json`. |
| 401 | `unauthorized` | `{"error":{"code":"unauthorized","message":"Missing or invalid API key.","request_id":"req_..."}}` | Check the `Authorization: Bearer ...` header and the key. |
| 402 | `insufficient_credit` | `{"error":{"code":"insufficient_credit","message":"Your credit balance is too low for this order.","balance":0,"required":0.15,"currency":"USD","request_id":"req_..."}}` | Top up, then send the request again. Nothing was charged. |
| 409 | `duplicate_order` | `{"error":{"code":"duplicate_order","message":"This email already received an invitation recently. Set \"allow_duplicate\": true to send again (charged).","request_id":"req_..."}}` | The same email was ordered recently. Send `"allow_duplicate": true` only if you really want to send (and be charged) again. Some duplicates cannot be re-sent at all and need support. |
| 409 | `request_in_progress` | `{"error":{"code":"request_in_progress","message":"A request with this Idempotency-Key is still being processed.","request_id":"req_..."}}` | Wait a few seconds and send the same request with the same key again. |
| 422 | `email_rejected` | see above | Not charged. Ask the buyer for a correct address. |
| 422 | `idempotency_conflict` | `{"error":{"code":"idempotency_conflict","message":"This Idempotency-Key was already used with a different email.","request_id":"req_..."}}` | Use a new key for a different email. |
| 429 | `rate_limited` | `{"error":{"code":"rate_limited","message":"Too many requests. Slow down.","request_id":"req_..."}}` | Wait for the number of seconds in the `Retry-After` header, then retry. |
| 503 | `temporarily_unavailable` | `{"error":{"code":"temporarily_unavailable","message":"We could not process this order right now. No credit was charged. Please retry shortly.","request_id":"req_..."}}` | Header `Retry-After: 30`. Retry after that, with the same `Idempotency-Key` if you sent one. |
| 503 | `out_of_capacity` | `{"error":{"code":"out_of_capacity","message":"We are temporarily out of capacity for new orders. No credit was charged. Please retry later.","request_id":"req_..."}}` | Not charged. We cannot fulfil new orders right now. Header `Retry-After: 300`: wait at least that long, then retry with the same `Idempotency-Key` if you sent one. Do not retry in a tight loop. |

Other statuses (`403`, `404`, `405`, `413`, `500`) are listed under [Errors](/errors).
