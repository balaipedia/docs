Sends one Canva Pro team invitation to one buyer email. The order is charged at your price when it is accepted.

## Headers

Required: `Authorization: Bearer YOUR_KEY` and `Content-Type: application/json`.

<ParamField header="Idempotency-Key" type="string">
  Optional, recommended. 8-64 characters (letters, digits, `_ . : -`), for example a UUID. Store it with your order so a retry reuses it.

  - **Why:** when a request times out or the connection drops, you cannot know whether the order was created. Repeat the request with the same key and the same email: you get the same order back (header `Idempotent-Replayed: true`) and are never charged twice.
  - Keys are remembered for 24 hours.
  - Reusing a key with a different email returns `422 idempotency_conflict`.
</ParamField>

<Warning>
  Without the key the request still works and the duplicate-email check (`409 duplicate_order`) still applies, but we cannot recognise a retry as the same request. Retrying a timed-out request that has `allow_duplicate: true` and no key can create and charge a second order.
</Warning>

## Body

<ParamField body="email" type="string" required>
  Buyer's email. One address per order, for example `buyer.name@gmail.com`.

  - Write a complete address with no spaces, commas or semicolons. Spaces before or after it are ignored and letters are lower-cased.
  - An address with a space or comma inside, such as `buyer @ gmail .com`, is rejected right away with `422 email_rejected` (`reason: "invalid_format"`).
  - Two addresses give `400 invalid_request`. To order for several buyers at once (up to 10), use [`POST /orders/bulk`](/api-reference/create-orders-bulk).
</ParamField>

<ParamField body="name" type="string">
  Optional. Used in the greeting (max 60 chars).
</ParamField>

<ParamField body="lang" type="string" default="en">
  `"en"` | `"id"`. Language of the email sent to the buyer: English or Indonesian. Default `"en"`. Any other value is rejected with `400`. This is independent of your account currency.
</ParamField>

<ParamField body="reference" type="string">
  Your own order reference (max 64). Returned in responses and webhooks; searchable via the list endpoint.
</ParamField>

<ParamField body="allow_duplicate" type="boolean">
  `true` or `false` only. By default an email that received an invitation in the last 30 days is refused with `409`. Set true to send again (charged). Re-sending is only allowed when the earlier invitation was one of your own orders; otherwise it is still refused with `409`.
</ParamField>

## Response

Returns the [order object](/api-reference/get-order#the-order-object) with status `201 Created`, plus `balance`: your balance after the charge.

## How an order is processed

`201` means the order was **accepted and charged**, not delivered yet. It always starts as `processing` and the response is instant. Follow the result with a [webhook](/webhooks) (recommended) or [`GET /orders/{id}`](/api-reference/get-order).

```text
processing  →  success                 (normal, usually within seconds)
processing  →  pending  →  success    (delivery was briefly delayed, we keep retrying)
processing  →  error                   (could not be delivered, charge refunded automatically)
```

Treat `processing` and `pending` as "in progress" and act only on `success` or `error`. If an order ends as `error`, the `note` explains why and the same email can be sent again as a new order.

## Rejected by validation, `422` (nothing charged)

A `422` means the email was rejected right away and nothing was charged (see the `422 Rejected` example). Some problems are only found after the order is accepted; those orders end as `error` with a `note` and a refund. Handle both.

- `reason`: a stable code you can branch on (table below).
- `note`: a short human-readable explanation you can log or show.

| reason | Meaning |
|--------|---------|
| `invalid_format` | Not a valid email format. |
| `typo_domain` | Likely typo in the domain; `suggestion` may contain the corrected address. |
| `domain_no_mail` | Domain does not exist or does not accept email. |
| `mailbox_not_found` | The mailbox does not exist. |
| `mailbox_full` | The recipient's inbox is full. Not a permanent block: ask the recipient to free up space and retry the same order after 3 hours. |
| `disposable_email` | Temporary / disposable email service. |
| `address_undeliverable` | This address previously failed or is on our block list. |
| `high_risk` | Flagged as risky (spam trap, abuse, do-not-mail). |
| `invalid_email` | Other validation failure. |

## Other failure responses

Every failure uses the same body, `{"error":{"code","message","request_id"}}`. Branch on `code`, not on `message`. A failed request never creates an order. Credit is charged only on `201`.

| HTTP | code | What to do |
| --- | --- | --- |
| 400 | `invalid_request` | Fix the request, do not retry unchanged. One email per request: no bulk, no list, and no comma-, semicolon- or space-separated addresses. |
| 400 | `invalid_json` | Send valid JSON with `Content-Type: application/json`. |
| 401 | `unauthorized` | Check the `Authorization: Bearer ...` header and the key. |
| 402 | `insufficient_credit` | Top up, then send the request again. Nothing was charged. |
| 409 | `duplicate_order` | The same email was ordered recently. Send `"allow_duplicate": true` only if you really want to send (and be charged) again. Some duplicates cannot be re-sent at all and need support. |
| 409 | `request_in_progress` | Wait a few seconds and send the same request with the same key again. |
| 422 | `email_rejected` | Not charged. Ask the buyer for a correct address. |
| 422 | `idempotency_conflict` | Use a new key for a different email. |
| 429 | `rate_limited` | Wait for the number of seconds in the `Retry-After` header, then retry. |
| 503 | `temporarily_unavailable` | Not charged. Header `Retry-After: 30`. Retry after that, with the same `Idempotency-Key` if you sent one. |
| 503 | `out_of_capacity` | Not charged, no order is created. Header `Retry-After: 300`: wait at least that long, then retry with the same `Idempotency-Key` if you sent one. Do not retry in a tight loop. |

<Note>
  **About `out_of_capacity`:** we cannot fulfil new orders right now. It can also be returned to one of several orders sent at the same moment, when the last remaining capacity was just taken by another order (from the API or the Telegram bot). Each order is decided on its own, so a request that gets this error simply did not get a place.
</Note>

Other statuses (`403`, `404`, `405`, `413`, `500`) are listed under [Errors](/errors).
