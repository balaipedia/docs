---
title: "Get order status"
description: "Get the status of one order."
api: "GET https://orders.balaipedia.com/v1/orders/{id}"
---

Returns one order created within the last 60 days (see [Data retention](/data-retention)). Poll sparingly; prefer [webhooks](/webhooks). An unknown order ID, or an order older than 60 days, returns `404 not_found`.

## Path parameters

<ParamField path="id" type="string" required>
  The order ID returned by `POST /orders`, e.g. `BP-7K3M9QXA`.
</ParamField>

## The order object

<ResponseField name="id" type="string">
  Order ID, e.g. `BP-7K3M9QXA`.
</ResponseField>

<ResponseField name="object" type="string">
  Always `"order"`.
</ResponseField>

<ResponseField name="email" type="string">
  Buyer's email (normalised to lowercase).
</ResponseField>

<ResponseField name="reference" type="string | null">
  Your reference, or `null` if you did not send one.
</ResponseField>

<ResponseField name="status" type="string">
  See [Order statuses](#order-statuses).
</ResponseField>

<ResponseField name="note" type="string | null">
  Only when `status` is `error`: a short, human-readable explanation of why the order failed (for example that the recipient's mailbox is full). `null` for every other status. The wording may be refined over time, so do not parse it: branch on `status`.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 UTC.
</ResponseField>

<ResponseField name="completed_at" type="string | null">
  When the current final status was set; `null` while not final.
</ResponseField>

<ResponseField name="expires_at" type="string | null">
  Subscription end date (`YYYY-MM-DD`) once known.
</ResponseField>

<ResponseField name="amount" type="number">
  Price charged for this order, in `currency`.
</ResponseField>

<ResponseField name="currency" type="string">
  `USD` or `IDR`.
</ResponseField>

<ResponseField name="refunded" type="boolean">
  Whether the charge was returned. An `error` order can be refunded automatically; an admin can also refund an order manually. A manual refund sets this to `true` and, if the order was `success`, changes its status to `error`.
</ResponseField>

<ResponseField name="balance" type="number">
  Only in the `201` response of `POST /orders`: your balance after the charge.
</ResponseField>

## Order statuses

| status | Meaning | Final? |
|--------|---------|--------|
| `pending` | Delivery is temporarily delayed and we keep retrying. Ends as `success`, or `error` if still undelivered after 72 hours. | No |
| `processing` | Accepted and charged. Being sent (normally seconds). Every new order starts here. | No |
| `success` | The invitation email was accepted by the recipient's mail server. (It does not mean the buyer has already joined.) | Yes |
| `error` | The invitation could not be delivered, or an admin refunded the order manually. We handle the cause on our side; check `refunded` to see whether the charge was returned. | Yes |

`success` and `error` are **final**. Delivery status does not change after an order reaches one of them. The only exception is an admin manual refund: a successful order can be refunded, which changes it to `error` with `refunded: true` and sends a later `order.error` event.

There are only these four statuses. Every failure is reported as `error`, and `note` tells you why, so an order never fails without an explanation:

```json
{"id":"BP-7K3M9QXA","object":"order","status":"error","note":"The recipient's mailbox is full.","refunded":true, ...}
```

Possible notes for `error` orders: the recipient's mailbox is full or does not exist; the email domain cannot receive email; the recipient's mail server rejected the email; the recipient reported the email as spam; the email could not be delivered within 72 hours; this email already received an invitation recently; we could not send the order right now (the credit is refunded, please retry shortly); the order was refunded manually by the admin; or a generic delivery failure.
