Instead of polling, register an HTTPS endpoint (public host, port 443). We POST an event whenever an order changes status. A webhook URL must be a public `https` URL on port 443 with a hostname (no IP addresses, no credentials in the URL).

| # | Method | URL | Body | Response |
| --- | --- | --- | --- | --- |
| 7 | `POST` | [`/webhook`](/api-reference/set-webhook) | `{"url":"https://..."}` | The webhook with a new signing `secret` (shown only once). POST again to change the URL or rotate the secret. |
| 8 | `GET` | [`/webhook`](/api-reference/get-webhook) | none | `{"object":"webhook","url":"https://...","enabled":true}` (`url` is `null` and `enabled` `false` when none is set). |
| 9 | `POST` | [`/webhook/disable`](/api-reference/disable-webhook) | none | `{"object":"webhook","url":null,"enabled":false}` |
| 10 | `POST` | [`/webhook/test`](/api-reference/test-webhook) | none | Sends a `webhook.test` event (empty `data`) to your URL and returns `{"delivered":true}` or `{"delivered":false}`. `false` means your endpoint did not answer `2xx` within 8 seconds. `400 invalid_request` if no webhook is configured. |

## Events and payload

Events: `order.pending`, `order.success`, `order.error` (one per status change, named after the new status). After `order.success` or `order.error` no further delivery event is sent for that order, except a later `order.error` when an admin refunds a successful order manually. The `data` object is the [order](/api-reference/get-order#the-order-object), including `amount`, `currency`, and `refunded`. Because orders are processed in the background, an `order.error` (with `refunded: true`) can arrive within seconds after the `201` response.

```http
POST https://example.com/hooks/orders
X-BP-Event: order.success
X-BP-Delivery: evt_5d1c0e7a2b9f4c33
X-BP-Timestamp: 1789000000
X-BP-Signature: v1=3f2a...

{"id":"evt_5d1c0e7a2b9f4c33","type":"order.success","created_at":"...","data":{ ...order object... }}
```

## Verify signatures

Verify every request: compute `HMAC-SHA256(secret, timestamp + "." + rawBody)` as lowercase hex, compare it to the value after `v1=` in constant time, and reject timestamps older than 5 minutes. Use the **raw** request body.

<Warning>
  Use the secret exactly as returned, including the `whsec_` prefix, as the HMAC key. Do not remove the prefix and do not base64-decode it (libraries made for other webhook services often do).
</Warning>

<CodeGroup>

```javascript Node.js
const crypto = require("crypto");
function verify(rawBody, headers, secret) {
  const ts = headers["x-bp-timestamp"];
  if (Math.abs(Date.now() / 1000 - Number(ts)) > 300) return false;
  const mac = crypto.createHmac("sha256", secret).update(ts + "." + rawBody).digest("hex");
  const got = String(headers["x-bp-signature"] || "").replace("v1=", "");
  return got.length === mac.length && crypto.timingSafeEqual(Buffer.from(mac), Buffer.from(got));
}
```

```php PHP
<?php
$raw = file_get_contents("php://input");
$ts  = $_SERVER["HTTP_X_BP_TIMESTAMP"] ?? "";
$sig = str_replace("v1=", "", $_SERVER["HTTP_X_BP_SIGNATURE"] ?? "");
$mac = hash_hmac("sha256", $ts . "." . $raw, $secret);
if (abs(time() - (int)$ts) > 300 || !hash_equals($mac, $sig)) { http_response_code(401); exit; }
```

```python Python
import hmac, hashlib, time
def verify(raw: bytes, ts: str, sig: str, secret: str) -> bool:
    if abs(time.time() - int(ts)) > 300: return False
    mac = hmac.new(secret.encode(), ts.encode() + b"." + raw, hashlib.sha256).hexdigest()
    return hmac.compare_digest(mac, sig.replace("v1=", ""))
```

</CodeGroup>

## Delivery and retries

Respond with any `2xx` within 8 seconds. Redirects are not followed: a `3xx` counts as a failed delivery, so register the final URL (for example the `https` address with the exact path, not one that redirects). Otherwise we retry with increasing delays (6 attempts in total, over about 15 hours). Retries reuse the same event `id` (also sent as `X-BP-Delivery`), so deduplicate on it. Delivery order is not guaranteed; if events arrive out of order, ignore an `order.pending` that comes after a final `order.success` or `order.error`, or fetch the order to confirm.
